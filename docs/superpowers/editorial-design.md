# PIXEL / VALUE — обновление по варианту 2

## Цель
Сделать существующее исследование визуально выразительнее и удобнее для чтения. Выбранный пользователем второй макет задаёт направление: тёмная поверхность, крупный заголовок слева, оригинальный игровой персонаж справа, бирюзовые акценты и сдержанные фиолетовые детали.

## Подходы
Рассмотрены три визуальные композиции: цифровой артефакт, редакционная композиция с персонажем и коллекция косметических предметов. Пользователь выбрал вторую. Она подчёркивает тему цифровой идентичности, сохраняя исследовательский характер. Первый вариант делает предмет главным героем, третий отдаёт больше места коллекции и меньше — объяснению исследования.

## Изменения
- Перестроить первый кадр по выбранному макету. Заголовок «Почему мы платим за пиксели», пояснение и основное действие слева; изображение персонажа справа. Сохранить название PIXEL / VALUE и существующие действия.
- Сгенерировать отдельное оригинальное изображение персонажа, не использовать весь макет как фон интерфейса. Добавить согласованные тематические изображения там, где они помогают объяснять самовыражение, редкость и принадлежность. Точное число и размещение определить после проверки доступного места в кадрах.
- Сохранить последовательность из 23 кадров, все результаты, знаменатели, оговорки, источники, авторство и год из текущего сайта. Не добавлять вымышленные данные.
- Настроить короткие направленные переходы кадров и последовательное появление содержимого; убрать конфликтующие повторные эффекты там, где они мешают. Анимации не должны задерживать навигацию или скрывать данные.
- Отключать декоративное движение при prefers-reduced-motion и ограничивать анимации неактивных кадров. На сенсорных устройствах не полагаться на hover.
- На узком экране размещать текст перед персонажем; сохранять доступ к кнопкам, навигации, карте кадров, обзору, документации и режиму докладчика.

## Реализация и границы
Развивать существующие HTML, CSS и vanilla JavaScript без перехода на новый фреймворк. Изображения хранить локально в assets. Сохранить клавиатурное управление и имеющиеся сценарии. Не менять настройки доступа, GitHub Pages и оформление приложения Codex. Figma использовать только при необходимости работы с конкретным дизайн-файлом; такого файла пользователь не указал.

Работать в отдельной ветке, подготовить изменения для просмотра. Слияние в main и публикация текущего GitHub Pages не входят в этот этап. Sites использовать для последующей публикации, когда пользователь запросит размещение; сначала показать проверенную локальную версию.

## Проверка
Запустить существующие проверки репозитория и проверку синтаксиса изменённого JavaScript. В браузере проверить первый экран и основные сценарии: переходы, карта кадров, обзор, документация, докладчик, клавиатура. Проверить широкую и мобильную компоновку, режим reduced-motion и ошибки консоли. Сравнить первый экран с выбранным макетом, исправить существенные расхождения. Недоступные проверки указать явно.

## Решения исполнителя
Точные интервалы анимаций, размеры изображений, сжатие, адаптивные пороги и способ устранения конфликтов существующих стилей выбираются по фактическому коду и проверке в браузере. Не расширять функциональность исследования.
